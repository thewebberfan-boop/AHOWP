# 系统复刻说明

本文是给下一位 AI、开发者或另一台电脑使用的产品与实现规格。它描述当前页面应当“是什么”、数据如何组织、交互必须保留哪些行为，以及如何在不依赖聊天记录的情况下复建项目。具体内容事实仍以 `app/*-data.ts` 和 `docs/PROJECT_STATUS.md` 为准。

## 1. 产品定位

这是一个围绕伯特兰·罗素《西方哲学史》的中文交互学习网站。它不是原书电子版，也不是按章节复述的百科，而是把历史知识组织成可下钻的关系结构：

`历史阶段 → 历史事件与时代问题 → 哲学流派 → 哲学家 → 概念与论证 → 原书章节`

设计目标是让历史型学习者用较低记忆成本建立高密度知识地图。原书目录是重要的回溯索引，但不是唯一的信息组织方式；人物和流派页面允许跨章节重组。

内容必须区分四种语气：罗素原书叙述、一般史实、现代研究校正、本站学习重构。人物之间必须区分直接承接、直接影响、共同传统、同题比较、批评关系和后世重构；不能因为观点相似就写成直接影响。

## 2. 页面模式与导航

顶部主导航依次为：

1. 原书结构
2. 哲学家
3. 哲学流派
4. 历史概览
5. 方法图谱
6. 原书索引
7. 关系复习

左侧栏根据模式切换索引：

- 原书结构：9 个历史阶段，显示年代、罗素原书范围和包含的流派数。
- 哲学家：完整人物索引、肖像、年代、学派和 1—5 星；点击顶部“哲学家”默认进入哲学家图谱，再由左侧人物卡进入人物详情。
- 哲学流派：17 个流派／传统页（第一卷 8 页、第二卷 9 页）；点击顶部“哲学流派”默认进入流派图谱，再由左侧流派卡进入流派详情。
- 原书索引：按第一卷、第二卷、第三卷筛选 76 个章节。
- 其他模式：显示对应阶段、方法或复习卡索引。
- 输入搜索词后，左侧栏改为跨层搜索结果，不同时显示普通索引。

顶部右侧保留全书路径和“中文／中英”术语开关。搜索、索引切换和下钻都必须保持在单页状态模型中，不要未经用户要求改成多路由应用。

## 3. 哲学家页面规格

当前有 53 位人物：第一卷 29 位、第二卷 24 位。顺序和 ID 由 `app/philosopher-data.ts` 汇总，第二卷人物内容位于 `app/philosopher-data-medieval.ts`。人物页的本地导航和 section 顺序固定为：

| 编号 | Section | 内容 |
| --- | --- | --- |
| 01 | 生平与历史位置 | 证据分层、时间线、地点和历史位置 |
| 02 | 核心概念 | 可点击的中英术语卡；概念数量按人物实际结构伸缩 |
| 03 | 研究对象与推导路径 | “研究对象 i: 对象 ｜ 问题”标题；逻辑起点、推导链、推导结果 |
| 04 | 关系定位与差异矩阵 | 思想来源、当前人物与流派位置、影响去向，以及比较表 |
| 05 | 故事、轶事与生活化入口 | 名言、故事、轶事或世俗辨识度举例；没有可靠材料时必须显示“无” |
| 06 | 罗素的解释与现代校正 | 罗素组织方式、现代补充、来源和原书章节跳转 |

必须保留的行为：

- 从流派页进入人物页时，人物页显示返回按钮；返回后恢复原流派和原滚动位置。
- 在人物页左侧索引切换人物时，右侧主体保持同一纵向阅读位置，不播放横向动画。
- 顶部人物序列只显示当前人物附近五人，避免复制左侧完整索引。
- 比较矩阵的“比较对象”列不得被长姓名撑破；表格允许自动列宽，窄屏时折成逐项卡片。
- 术语显示中文和英语释义；希腊语、拉丁语及转写在点击弹窗中显示。术语和后续中文不得被人为拆成孤立换行。
- 人物肖像保持原有非正方形比例；左侧人物索引中的星标紧贴肖像下方，流派详情中的人物卡将星级以肖像右下角叠层显示，两处都不得增加不必要的卡片高度。星级为 1—5，搜索 `5星`、`4星` 或 `★` 可命中人物。
- 轶事资料不足时显示“无”，不能把整个 Section 隐藏成像 bug 的空白。

## 4. 哲学家关系图谱

入口位于哲学家左侧索引顶部，使用 `↔` 作为关系入口符号，并沿用流派图谱相同的纸张、墨色、暗红、深绿和浅绿系统。图谱不是一套手工维护的第二份关系数据，而是从每位人物的 `comparisons` 自动汇总、去重生成：

- 当前规模：53 个人物节点、140 条关系边。
- `承接前人`：方向反转为“前人 → 当前人物”。
- `影响后继`：当前人物 → 后继人物。
- `同题比较`：双向关系，不显示箭头。
- `批评关系`：双向张力关系，不显示箭头。
- `后世重构`：当前人物 → 后世解释对象。

页面只呈现一张 D3.js 多类型节点力导向网络图：按六个历史阶段形成多中心聚类，节点颜色表达阶段类型，并以实际人物关系连接跨群节点。交互必须包括：

1. 关系图例：五种关系的颜色和线型不同。
2. “显示全部关系”按钮：取消节点聚焦。
3. 点击人物节点：该人物保持强调，与其相连的边保持清晰，其余节点和边淡出。
4. 详情面板：列出关系类型、方向、双方人物和由 `shared`／`difference` 组成的证据说明。
5. 拖动节点、拖动空白平移、滚轮／双指缩放，以及放大、缩小、复位按钮。
6. “进入人物页”：关闭图谱并打开对应人物页。

图谱使用 1000×440 的统一 D3 视区，控制单个图谱在常见桌面屏幕内的纵向占用；窄屏使用 900px 最小画布宽度，保留可读字号并允许横向滚动，而不是把整图压缩成不可读缩略图。详情卡在移动端折为单列。SVG 节点必须具有 `role="button"`、键盘 Enter／Space 操作和描述性 `aria-label`。

## 5. 哲学流派页与流派图谱

当前有 17 个流派／传统页：第一卷 8 页，第二卷 9 页。第二卷新增“教父哲学与拉丁基督教传统”“西方修道制度与教牧思想”“中世纪基督教新柏拉图主义”“伊斯兰哲学：法尔萨法与卡拉姆批评”“中世纪犹太哲学”“十二世纪辩证法与共相论”“多明我会亚里士多德综合”“方济各会经院哲学与唯名论”“中世纪政教权力思想”。流派页统一使用“时代压力 → 共同问题 → 共享前提 → 方法 → 代表性回答 → 内部张力”的结构，再连接人物、发展阶段、关系、影响、罗素解释、现代校正、来源和原书章节。

每位现有人物必须至少进入一个流派／传统页；同一人物可以因承担不同历史功能进入多个页面。页面必须明确自己属于有组织学园、宗教传统、修会思想、问题共同体或现代史学统称，不能为了目录整齐制造虚假的统一学派。伊斯兰、犹太与拉丁基督教传统按各自问题语境呈现，不能只写成向拉丁欧洲输送希腊材料的过渡桥梁。

在流派页左侧索引切换流派时，右侧主体必须与人物索引切换保持一致：保存当前窗口纵向坐标，替换内容后用 `behavior: "auto"` 在两帧内恢复，不播放滚动或横向动画。流派大标题在三栏并列的桌面布局中保持单行，并根据标题实际渲染宽度从 48px 向下拟合至最低 20px；标题侧与右侧事实表使用同一网格行高度。1050px 以下事实表换行后恢复普通响应式标题，不强制压缩为过小字号。

流派图谱从总流派数组的关系数据自动汇总并去重，当前为 17 个节点、57 条内部关系、6 条外部延伸。页面只呈现一张 D3.js 多类型节点力导向网络图，按“古代哲学传统、教父／修道／新柏拉图、伊斯兰与犹太、中世纪经院、政教权力”形成多中心聚类，并以实际流派关系连接跨组节点。现有关系类型为：思想来源、竞争、分化、吸收改造、后世重构。竞争使用虚线，定向关系使用箭头；拖拽、缩放、复位、关系详情和进入流派页的交互应与哲学家图谱保持一致。

## 6. 全局交互

- 搜索覆盖阶段、回应、流派、人物、方法、章节、地点和术语，最多展示 40 条结果。
- 地名可点击打开地点弹窗；术语可点击打开双语／词源弹窗；弹窗必须有遮罩、关闭按钮和 Escape 支持。
- 原书章节页面可从结构、历史、流派、人物、方法或复习视图进入，并能返回进入前的模式和选择。
- 章节可记录笔记、收藏、复制 PDF 页码；复习视图支持翻卡和标记已复习。
- 地图和外部资料链接可联网使用；离线版保证正文、搜索、弹窗、复习和本地人物图片可用，但不保证在线地图和外部页面。
- 所有新交互必须兼顾键盘、触摸屏和窄屏；不要加入未经用户要求的动画。

## 7. 数据与代码结构

- `app/page.tsx`：单页状态、模式切换、侧栏、搜索、主要视图组件和返回位置逻辑。
- `app/philosopher-data.ts`：人物类型、第一卷前期人物、总人物数组、旧人物生活化笔记与星级。
- `app/philosopher-data-late-ancient.ts`：后续／晚期人物资料扩展。
- `app/philosopher-data-medieval.ts`：第二卷 24 位人物的生平、概念、推导、关系、生活化笔记、星级和来源。
- `app/d3-force-graph.tsx`：可复用的 D3.js 力导向布局、SVG 绘制、节点拖拽、缩放、复位和键盘操作。
- `app/philosopher-graph.tsx`：哲学家关系边生成、阶段分组、单图配置和详情面板。
- `app/school-data.ts`：流派类型、第一卷 8 页、总流派数组与关系汇总。
- `app/school-data-medieval.ts`：第二卷 9 个流派／传统页、人物卡与关系。
- `app/school-graph.tsx`：流派关系数据适配、传统分组、单图配置和详情面板。
- `app/russell-structure-data.ts`：9 个历史阶段的重构结构。
- `app/book-data.ts`：三卷、76 章及已有章节笔记。
- `app/history-data.ts`：历史概览、事件、时代问题和复习资料。
- `app/terminology-data.ts`：可点击的中英术语及词源信息。
- `app/geography-data.ts`：地点和历史地图信息。
- `app/figure-data.ts`、`visual-archive/figures.json`、`public/visual-archive/figures/`：肖像资产、来源、许可和本地文件。
- `app/globals.css`：纸张视觉系统、表格、图谱、响应式断点和弹窗样式。
- `offline/` 与 `offline-reader/index.html`：离线构建入口和生成交付文件。

新增内容优先进入对应 `*-data.ts`，不要继续把大段知识资料塞进 `page.tsx`。新增人物图像必须同时提交本地文件和许可记录；不要用生成图像替代已有历史图像。

## 8. 视觉约束

基础色由 `app/globals.css` 的变量控制：纸张 `--paper`、浅纸 `--paper-light`、墨色 `--ink`、灰色 `--muted`、线条 `--line`、暗红 `--red`、深绿 `--green`、浅绿 `--green-soft`。新组件应复用这些变量和既有 `.page-wrap`、`.school-map-*`、`.profile-*` 结构，不另起颜色体系。

桌面端使用左侧固定索引栏和右侧阅读窗；约 760px 以下切为上下结构，侧栏有固定高度，顶部导航可横向滚动，图谱画布保留横向滚动。表格、关系链和卡片应优先使用 `minmax(0, 1fr)`、`min-width: 0` 和自动列宽，避免中文姓名、双语标签和关系文本溢出。

## 9. 本地运行、构建与交接

环境要求：Node.js `>=22.13.0`，推荐 `.nvmrc` 的 `24.19.0`。项目使用 React 19、vinext、Vite、TypeScript 和 D3.js 7，不要替换框架或锁文件体系。

```bash
nvm install
nvm use
npm ci
npm run dev
```

常用验证：

```bash
npm run lint
npm run build
npm run build:offline
npm test
```

两台电脑交替工作时，先读 `AGENTS.md`、`README.md`、本文和 `docs/PROJECT_STATUS.md`，确认 `git status --short`，再执行 `git pull --ff-only origin main`。依赖和 `dist` 放在 OneDrive 之外的本地运行目录，具体命令见 `docs/MULTI_MACHINE_WORKFLOW.md`。

一个完整功能形成一个聚焦提交。提交前更新 `docs/PROJECT_STATUS.md`，确认 `git diff --check`、构建和离线入口均通过；用户明确要求同步时，推送到 `origin main`。不要使用强制推送、`git reset --hard` 或覆盖式 checkout。

## 10. 当前范围与不要擅自扩张的内容

当前范围覆盖第一卷 29 位古代人物、第二卷 24 位教父、中世纪伊斯兰／犹太思想家及经院哲学家，以及连接这些人物的 17 个流派／传统页。第二卷人物收录标准是“原书中被实质讨论、能够形成独立思想页面”，不是把每个教皇、君主或章节中出现的人名都页面化；安布罗斯、本尼狄克、大格列高利等主要以制度与实践思想进入，并必须明确身份边界。现有 53 位人物中 52 位已有经来源与许可记录的历史图像；罗瑟林因尚未找到可可靠识别的图像，明确保留姓名字标。第一卷遗漏人物、第三卷、更多章节笔记、完整人物交叉索引、可分享 URL、多路由详情页和完全离线地图仍属后续范围。另一个 AI 接手时应先根据 `docs/PROJECT_STATUS.md` 选择一个经用户确认的方向，不要继续批量生成全书人物资料或先造空壳目录。
