# 系统复刻说明

本文是给下一位 AI、开发者或另一台电脑使用的产品与实现规格。它描述当前页面应当“是什么”、数据如何组织、交互必须保留哪些行为，以及如何在不依赖聊天记录的情况下复建项目。具体内容事实仍以 `app/*-data.ts` 和 `docs/PROJECT_STATUS.md` 为准。

## 1. 产品定位

这是一个围绕伯特兰·罗素《西方哲学史》的中文交互学习网站。它不是原书电子版，也不是按章节复述的百科，而是把历史知识组织成可下钻的关系结构：

`历史阶段 → 历史事件与时代问题 → 哲学流派 → 哲学家 → 概念与论证 → 原书章节`

设计目标是让历史型学习者用较低记忆成本建立高密度知识地图。原书目录是重要的回溯索引，但不是唯一的信息组织方式；人物和流派页面允许跨章节重组。

内容必须区分四种语气：罗素原书叙述、一般史实、现代研究校正、本站学习重构。人物之间必须区分直接承接、直接影响、共同传统、同题比较、批评关系和后世重构；不能因为观点相似就写成直接影响。

## 2. 页面模式与导航

网站根入口先显示独立首页，不直接渲染带侧栏的历史页面。首页必须提供两个清晰入口：

1. “开始历史之旅”：打开 `historyStages[0]`，同时选中该阶段的第一项回应并置顶。
2. “继续上次学习”：恢复上次的页面模式、选中阶段／回应／流派／人物／问题图谱节点／方法／章节、图谱或详情状态、复习索引、纵向滚动位置，以及 `chapterOrigin`、`schoolOrigin`、`philosopherOrigin`、`problemHistoryOrigin` 组成的返回链。

学习状态使用版本化的 `ahowp-learning-session-v1` 存入当前浏览器 `localStorage`。首页不得被保存成“上次学习页面”；没有记录时“继续”入口保持可见但不可用，并明确说明首次学习后才会生成记录。进入学习界面后，左上角站点标题是返回首页的入口，点击时必须先同步保存当前位置。该记录只属于当前浏览器，不承诺跨设备或跨浏览器同步。

顶部主导航依次为：

1. 历史概览
2. 哲学流派
3. 哲学家
4. 问题图谱
5. 原书索引
6. 方法图谱
7. 关系复习

左侧栏根据模式切换索引：

- 历史概览：11 个学习阶段，是首页“开始历史之旅”进入后的默认学习主线；每个阶段在事件、问题、回应、流派和人物之后，显示对应的罗素目录框架与章节组。
- 哲学家：完整人物索引、肖像、年代、个人资料中的流派文字和 1—5 星学习辨识度；82 人按 34／24／14／7／3 的近似对数金字塔分布，五星仅为苏格拉底、柏拉图、亚里士多德。详情页的规范流派入口由流派资料反向确定。点击顶部“哲学家”默认进入哲学家图谱，再由左侧人物卡进入人物详情。
- 哲学流派：32 个流派／传统、问题取向与方法转型页（第一卷 8 页、第二卷 9 页、第三卷 15 页），索引显示 1—5 星学习辨识度；流派按 12／9／5／4／2 的近似对数金字塔分布，五星仅为柏拉图主义与亚里士多德主义。点击顶部“哲学流派”默认进入流派图谱，再由左侧流派卡进入流派详情。
- 问题图谱：左侧显示当前选中节点的详情，不把维护分组或哲学家当作导航节点。当前谱系“从多样与变化到规程、教牧与教会秩序”以 115 个节点、146 条有向边覆盖泰勒斯至大格列高利，包括第一卷全部 30 章、现有 29 位第一卷人物，以及第二卷第一至七章和八位人物。
- 原书索引：按第一卷、第二卷、第三卷筛选 76 个章节。
- 其他模式：显示对应阶段、方法或复习卡索引。
- 输入搜索词后，左侧栏改为跨层搜索结果，不同时显示普通索引。

进入历史概览、哲学流派或哲学家模式时，侧栏滚动区必须将当前对应项无动画定位到可视区域的中间：历史模式为当前阶段卡，流派／人物详情为当前卡，关系图谱状态为各自图谱入口。问题图谱没有阶段索引，左侧随图中选择更新节点详情。搜索结果视图不强制改写用户自己的侧栏滚动位置。

在手机竖屏断点（`max-width: 760px`）下，历史概览、哲学流派和哲学家隐藏桌面侧栏，并在顶部导航下显示同一数据来源的横向对象轨道。问题图谱同样隐藏侧栏，但不显示维护分组轨道，完整图按正文宽度呈现，详情置于图后。手机搜索从顶部的紧凑搜索按钮进入；其他页面保持既有索引方式。

顶部右侧保留全书路径和“中文／中英”术语开关。搜索、索引切换和下钻都必须保持在单页状态模型中，不要未经用户要求改成多路由应用。

历史概览与罗素原书必须保留两种分期之间的差异：历史概览使用 11 个较细的学习阶段，罗素目录数据保留 9 个较宽的重构框架。后者不再作为独立页面，而由 `russellStructureStageIdsByHistoryStage` 显式映射到每个历史阶段的“罗素原书中的位置”区块。该区块只承担原书范围、组织线索和章节入口，不重复历史事件、时代问题、流派详情和人物卡。

### 问题图谱模式

问题图谱是跨人物的逻辑阅读层，不是第三张人物／流派关系图。它使用稳定、可按顺序阅读的确定性 SVG 有向图，不使用 D3 力导向布局。节点只有观察、问题和答案；区分、反驳、修复、转向等作为答案角色保留，哲学家只以参与者身份附着在节点上。

问题图谱的完整字段语义、连接证据等级、现有阶段与节点稳定 ID、续写步骤、多谱系前置改造和验收命令见 `docs/PROBLEM_MAP_GUIDE.md`。实现第二条谱系前必须先按该文档增加 `problemMapId` 状态；当前界面仍直接渲染第一条 `ancientDifferenceProblemMap`。节点详情区只负责解释当前节点、显示逻辑压力、参与人物、流派和原书入口；来路与去向由图上的有向边表达，不在左侧重复列邻接节点。

当前谱系为“从多样与变化到规程、教牧与教会秩序”，范围是泰勒斯至大格列高利，共 12 个内部维护分组、115 个节点和 146 条边：

1. 先把并存多样、时间变化、条件关联、周期重复和过程持续拆为五个可重叠的自然经验观察；
2. 由它们多对多地提出来源、同一、动力和秩序四个问题，再比较米利都路线、数与比例及赫拉克利特式对立过程；
3. 由巴门尼德与埃利亚的芝诺施加存在、运动和多样的逻辑压力；
4. 由恩培多克勒、阿那克萨哥拉和原子论以不变构成的重新配置保存变化；
5. 把性质问题推进到感觉事件、普罗泰戈拉式显现、苏格拉底式定义与柏拉图式稳定知识对象；雅典公共生活中的意见冲突作为后续社会制度观察，连接共同判断标准问题。
6. 由柏拉图的分有、灵魂、政治和宇宙论进入亚里士多德的质料—形式、潜能—现实、四因、逻辑和科学说明；
7. 由功能解释进入幸福、德性、实践智慧与城邦，再由城邦政治脆弱性重新提出个人自由；
8. 比较犬儒的低依赖、怀疑的悬置、伊壁鸠鲁的自然治疗与斯多葛的因果秩序；
9. 继续处理认知印象、无确定性行动、兼容论责任、友谊契约、角色义务和世界城邦；
10. 由罗马帝国的法律扩张和意义危机进入普罗提诺的太一—精神—灵魂、流溢—回归与非实体恶，并以第二卷问题收束。
11. 由经文共同体的有方向历史进入创造与救赎，比较斐洛、奥利金、哲罗姆的解释工具和安布罗斯的政教边界，再以奥古斯丁的恶、分裂意志、恩典、时间与两座城综合，并向修道与教牧制度开放。
12. 由西罗马制度断裂进入波爱修斯的命运、天意、自由与逻辑传输，再以本尼狄克规程和大格列高利的差别教牧、教皇网络处理共同生活与组织保存，最后向教会改革问题开放。

每条边必须符合观察→问题“提出问题”、问题→答案“回应问题”、答案→问题“产生问题”的方向语法，并另标“原书线索、历史回应、同题并列、本站推演、后世重构”之一。左侧详情同时显示“为什么进入图谱”和“它又留下什么”，并连接参与人物、流派和原书章节。观察的领域与解释只放在节点详情，不显示于主图；历史事件、制度或社会变化确实改变问题条件时，可增加历史概览入口。进入历史后必须能返回原问题节点和滚动位置。十二个维护分组不得重新成为左侧或正文导航；内容审计必须保证第一卷 30 章、现有 29 位第一卷人物，以及第二卷前七章和八位人物全部有图谱入口。

## 3. 哲学家页面规格

当前有 82 位人物：第一卷 29 位、第二卷 24 位、第三卷 29 位。顺序和 ID 由 `app/philosopher-data.ts` 汇总，第二、三卷人物内容分别位于 `app/philosopher-data-medieval.ts` 与 `app/philosopher-data-modern.ts`。人物页的本地导航和 section 顺序固定为：

| 编号 | Section | 内容 |
| --- | --- | --- |
| 01 | 生平与历史位置 | 证据分层、时间线、地点和历史位置 |
| 02 | 核心概念 | 可点击的中英术语卡；概念数量按人物实际结构伸缩 |
| 03 | 研究对象与推导路径 | “研究对象 i: 对象 ｜ 问题”标题；逻辑起点、推导链、推导结果 |
| 04 | 关系定位与差异矩阵 | 思想来源、当前人物与流派位置、影响去向；由流派资料反向生成的“本站关联流派”入口；以及比较表 |
| 05 | 故事、轶事与生活化入口 | 可并列多条生活场景、文本例子、思想实验、名言或轶事；五星至少 3 条、四星至少 2 条、三星至少 1 条。没有可靠材料时显示“无” |
| 06 | 罗素的解释与现代校正 | 罗素组织方式、现代补充、来源和原书章节跳转 |

必须保留的行为：

- 从流派页进入人物页时，人物页显示返回按钮；返回后恢复原流派和原滚动位置。
- 从人物页进入“本站关联流派”时，流派页显示返回按钮；返回后恢复原人物页和原滚动位置，并继续保留此前的历史或流派返回链。
- 在人物页左侧索引切换人物时，右侧主体保持同一纵向阅读位置，不播放横向动画。
- 人物详情页不显示前后人物序列，避免复制左侧完整索引；若由历史或流派页进入，返回箭头置于本页置顶章节导航的最左侧。
- 章节导航保持置顶，并依据当前滚动阅读位置高亮对应章节；点击导航仍使用锚点跳转。
- 比较矩阵的“比较对象”列不得被长姓名撑破；表格允许自动列宽，窄屏时折成逐项卡片。
- 术语显示中文和英语释义；希腊语、拉丁语及转写在点击弹窗中显示。术语和后续中文不得被人为拆成孤立换行。
- 人物肖像保持原有非正方形比例；左侧人物索引中的星标紧贴肖像下方，流派详情中的人物卡将星级以肖像右下角叠层显示，两处都不得增加不必要的卡片高度。星级为 1—5，按 34／24／14／7／3 的近似对数金字塔分布；它表示学习路径中的解释广度与优先次序，不评价人物的哲学价值。搜索 `5星`、`4星` 或 `★` 可命中人物。
- 轶事资料不足时显示“无”，不能把整个 Section 隐藏成像 bug 的空白。

## 4. 哲学家关系图谱

入口位于哲学家左侧索引顶部，使用 `↔` 作为关系入口符号，并沿用流派图谱相同的纸张、墨色、暗红、深绿和浅绿系统。图谱不是一套手工维护的第二份关系数据，而是从每位人物的 `comparisons` 自动汇总、去重生成：

- 当前规模：82 个人物节点、203 条去重关系边。
- `承接前人` 与 `影响后继` 是同一条直接传承边的两端视角：图中只保留“前人 → 后人”一条箭头；聚焦接收者时显示“承接前人”，聚焦给予者时显示“影响后继”。
- `同题比较`：双向关系，不显示箭头。
- `批评关系`：双向张力关系，不显示箭头。
- `后世重构`：由较早的思想资源指向较晚的重释者；原始证据可记录在任意一方人物页。

页面只呈现一张 D3.js 多类型节点力导向网络图：按与流派图谱相同的九个历史—方法群形成多中心聚类，节点颜色表达规范流派分类，并以实际人物关系连接跨群节点。人物节点的流派副标签须由流派资料反向生成，不得以人物资料中的自由文本代替。交互必须包括：

1. 关系图例：五种关系的颜色和线型不同。
2. “显示全部关系”按钮：取消节点聚焦。
3. 点击人物节点：该人物保持强调，与其相连的边保持清晰，其余节点和边淡出。
4. 详情面板：列出关系类型、方向、双方人物和由 `shared`／`difference` 组成的证据说明。
5. 拖动节点、拖动空白平移、滚轮／双指缩放，以及放大、缩小、复位按钮。
6. “进入人物页”：关闭图谱并打开对应人物页。

图谱使用 1000×440 的统一 D3 视区，控制单个图谱在常见桌面屏幕内的纵向占用；窄屏使用 900px 最小画布宽度，保留可读字号并允许横向滚动，而不是把整图压缩成不可读缩略图。详情卡在移动端折为单列。SVG 节点必须具有 `role="button"`、键盘 Enter／Space 操作和描述性 `aria-label`。

## 5. 哲学流派页与流派图谱

当前有 32 个流派／传统、问题取向与方法转型页：第一卷 8 页、第二卷 9 页、第三卷 15 页。第二卷新增“教父哲学与拉丁基督教传统”“西方修道制度与教牧思想”“中世纪基督教新柏拉图主义”“伊斯兰哲学：法尔萨法与卡拉姆批评”“中世纪犹太哲学”“十二世纪辩证法与共相论”“多明我会亚里士多德综合”“方济各会经院哲学与唯名论”“中世纪政教权力思想”。第三卷新增“文艺复兴政治现实主义”“基督教人文主义”“宗教改革与新教思想”“科学革命与经验方法”“机械论政治哲学”“大陆理性主义”“英国经验主义与自由主义”“浪漫主义批判与共和自由”“批判哲学与德国观念论”“意志与价值哲学”“功利主义”“历史唯物主义与资本主义批判”“生命哲学与直觉主义”“实用主义”“逻辑分析哲学”。前四类明确保留其问题取向、知识网络或方法转型的边界，而不伪装成自称学派。流派页统一使用“时代压力 → 共同问题 → 共享前提 → 方法 → 代表性回答 → 内部张力”的结构，再连接人物、发展阶段、关系、影响、罗素解释、现代校正、来源和原书章节。

每位现有人物必须至少进入一个流派／传统页；同一人物可以因承担不同历史功能进入多个页面。页面必须明确自己属于有组织学园、宗教传统、修会思想、问题共同体或现代史学统称，不能为了目录整齐制造虚假的统一学派。伊斯兰、犹太与拉丁基督教传统按各自问题语境呈现，不能只写成向拉丁欧洲输送希腊材料的过渡桥梁。

在流派页左侧索引切换流派时，右侧主体必须与人物索引切换保持一致：保存当前窗口纵向坐标，替换内容后用 `behavior: "auto"` 在两帧内恢复，不播放滚动或横向动画。流派大标题在三栏并列的桌面布局中保持单行，并根据标题实际渲染宽度从 48px 向下拟合至最低 20px；标题侧与右侧事实表使用同一网格行高度。1050px 以下事实表换行后恢复普通响应式标题，不强制压缩为过小字号。

流派星级按 12／9／5／4／2 的近似对数金字塔分布，表示学习路径中的解释广度与优先次序而非哲学价值判断。五星只保留柏拉图主义与亚里士多德主义。星标放在左侧索引序号下方，以紧凑小字号占用既有纵向空间，不增加索引卡高度，也不进入详情页的大标题或事实表。搜索 `5星`、`4星` 或 `★` 可同时命中对应流派。

流派图谱从总流派数组的关系数据自动汇总并去重，当前为 32 个节点；内部与外部关系数由数据自动显示。页面只呈现一张 D3.js 多类型节点力导向网络图，按“古代哲学传统、教父／修道／新柏拉图、伊斯兰与犹太、中世纪经院、政教权力、文艺复兴／改革／新科学、近代国家／理性／经验、自由／观念论／价值批判、工业社会／现代方法”形成多中心聚类，并以实际流派关系连接跨组节点。现有关系类型为：思想来源、竞争、分化、吸收改造、后世重构。竞争使用虚线，定向关系使用箭头；拖拽、缩放、复位、关系详情和进入流派页的交互应与哲学家图谱保持一致。

## 6. 全局交互

- 搜索覆盖阶段、回应、流派、人物、问题图谱、方法、章节、地点和术语，最多展示 40 条结果；问题图谱搜索同时包含观察领域、观察说明及历史关联文字。
- 已建立独立详情页的哲学家和流派术语（以 `TermEntry.entity` 标记）点击后直接进入对应页面，以深绿虚线和 `↗` 表示下钻；必须保存来源模式、选中对象、既有返回链与精确滚动位置，详情页的返回按钮逐层恢复。概念、地点、著作及尚未建立独立页的人物仍使用弹窗：地名打开地点弹窗，其余术语打开双语／词源弹窗；弹窗必须有遮罩、关闭按钮和 Escape 支持。
- 原书章节页面可从结构、历史、流派、人物、问题图谱、方法或复习视图进入，并能返回进入前的模式和选择。
- 历史概览只保留左侧 11 阶段索引，不在正文重复横向阶段导航。每种“同期回应”通过显式 ID 数据连接相关流派和关键哲学家；进入详情前保存阶段、回应和纵向滚动位置，返回时恢复原位置。历史 → 流派 → 哲学家按两级返回链逐层回退。正文中的已建档人物与流派名称可直接下钻，但历史阶段、流派、哲学家和原书章节的页面主标题始终是静态身份展示，不提供链接、弹窗或键盘焦点。
- 学习会话在状态变化、滚动停止和页面离开时更新；恢复期间先完成页面与对象切换，再以无动画滚动定位，避免恢复过程把原位置误存为页面顶部。人物或流派来自已有下钻链时，使用左侧索引切换同类对象不得清除这条返回链。
- 章节可记录笔记、收藏、复制 PDF 页码；复习视图支持翻卡和标记已复习。
- 地图和外部资料链接可联网使用；离线版保证正文、搜索、弹窗、复习和本地人物图片可用，但不保证在线地图和外部页面。
- 所有新交互必须兼顾键盘、触摸屏和窄屏；不要加入未经用户要求的动画。

## 7. 数据与代码结构

- `app/page.tsx`：单页状态、模式切换、侧栏、搜索、主要视图组件和返回位置逻辑。

- `app/philosopher-data-late-ancient.ts`：后续／晚期人物资料扩展。

- `app/philosopher-graph.tsx`：哲学家关系边生成、阶段分组、单图配置和详情面板。
- `app/problem-map-data.ts`：问题谱系、思想节点、连接证据类型、参与人物与原书章节映射。
- `app/problem-map.tsx`：确定性有向问题图、当前节点详情、人物与章节下钻。
- `app/school-data.ts`：流派类型、第一卷 8 页、总流派数组与关系汇总。
- `app/school-data-medieval.ts`：第二卷 9 个流派／传统页、人物卡与关系。
- `app/school-graph.tsx`：流派关系数据适配、传统分组、单图配置和详情面板。
- `app/russell-structure-data.ts`：依据罗素目录保留的 9 个较宽重构框架，以及它们与 11 个历史概览阶段的显式映射。
- `app/book-data.ts`：三卷、76 章及已有章节笔记。
- `app/history-data.ts`：历史概览、事件、时代问题、复习资料，以及同期回应到流派／人物详情的显式连接。
- `app/terminology-data.ts`：可点击的中英术语及词源信息。
- `app/geography-data.ts`：地点和历史地图信息。
- `app/figure-data.ts`、`visual-archive/figures.json`、`public/visual-archive/figures/`：肖像资产、来源、许可和本地文件。

## 8. 视觉约束

基础色由 `app/globals.css` 的变量控制：纸张 `--paper`、浅纸 `--paper-light`、墨色 `--ink`、灰色 `--muted`、线条 `--line`、暗红 `--red`、深绿 `--green`、浅绿 `--green-soft`。新组件应复用这些变量和既有 `.page-wrap`、`.school-map-*`、`.profile-*` 结构，不另起颜色体系。

桌面端使用左侧固定区和右侧阅读窗；历史、流派和人物在左侧显示索引，问题图谱则显示当前节点详情。约 760px 以下隐藏侧栏，历史、流派和人物使用横向对象轨道，问题图谱直接按宽度呈现完整图。人物／流派力导向图可保留横向滚动；问题图谱不得出现内部横向滚动。

## 9. 本地运行、构建与交接

环境要求：Node.js `>=22.13.0`，推荐 `.nvmrc` 的 `24.19.0`。项目使用 React 19、vinext、Vite、TypeScript 和 D3.js 7，不要替换框架或锁文件体系。

```bash
nvm install
nvm use
npm ci
npm run dev
```

```bash

```

两台电脑交替工作时，先读 `AGENTS.md`、`README.md`、本文和 `docs/PROJECT_STATUS.md`，确认 `git status --short`，再执行 `git pull --ff-only origin main`。继续问题图谱时还要完整阅读 `docs/PROBLEM_MAP_GUIDE.md`。依赖和 `dist` 放在 OneDrive 之外的本地运行目录，具体命令见 `docs/MULTI_MACHINE_WORKFLOW.md`。

一个完整功能形成一个聚焦提交。提交前更新 `docs/PROJECT_STATUS.md`，确认 `git diff --check`、构建和离线入口均通过；用户明确要求同步时，推送到 `origin main`。不要使用强制推送、`git reset --hard` 或覆盖式 checkout。
