# 问题图谱：内容模型、实现边界与续作手册

本文说明“问题图谱”为什么存在、怎样用三类节点组织材料，以及另一台电脑如何在不依赖聊天记录的情况下继续扩展。图负责表达节点之间的来路与去向，节点详情区不重复列出邻接节点。

## 1. 目标：把哲学史读成问题网络

历史阶段仍是全站首要骨架，流派和哲学家仍是主要下钻对象。问题图谱提供另一种阅读尺度：

> 人们观察到什么 → 为什么必须提问 → 有哪些并行或竞争答案 → 每个答案又留下什么新问题。

这不是一条单线思想进化史。一个观察可以提出多个问题，一个问题可以得到多个答案，一个答案可以产生多个新问题；同一问题也可能同时承接若干较早答案留下的压力。底层结构因此是有向、多对多的关系图，而不是按人物或阶段排列的卡片列表。

哲学家只是节点的历史参与者；图的节点只有观察、问题与答案。

## 2. 方法来源与本站取舍

这一组织法与几种已有传统相邻：问题史把哲学史组织为问题及回答的延续；柯林武德的“问答逻辑”强调必须以问题理解答案；杜威、波普尔和劳丹分别把探究或知识推进理解为问题、试探性答案、批评及新问题；IBIS 等问题映射方法则证明了问题与回应适合用图数据表达。

本站不照搬其中任何一套体系。尤其要避免把不同年代的问题误写成永恒不变的同一问题，也不把现代会议决策语法直接套在哲学史上。本站只吸收三项共同洞见：

- 用问题而非人物名单组织跨时代比较；
- 用显式有向边保留一对多和多对多关系；
- 用证据等级区分历史回应与编辑性重建。

参考入口：

- [SEP · Wilhelm Windelband](https://plato.stanford.edu/entries/wilhelm-windelband/)
- [SEP · Robin George Collingwood](https://plato.stanford.edu/entries/collingwood/)
- [SEP · John Dewey](https://plato.stanford.edu/entries/dewey/)
- [Karl Popper · Science: Conjectures and Refutations](https://www.marxists.org/reference/subject/philosophy/works/at/popper.htm)
- [Rittel & Webber · Dilemmas in a General Theory of Planning](https://escholarship.org/uc/item/5cj786v8)

## 3. 三类节点

`ProblemNodeKind` 只允许三类。

### 观察

观察是尚未由图内其他答案产生的问题来源，例如经验差异、历史处境、实践冲突或语言现象。它不是“无理论的纯事实”，必须写清看见了什么，以及它为何形成解释压力。

观察只通过“提出问题”指向问题，当前模型不允许其他节点指向观察。

每个观察还必须保存 `observation.domain` 与 `observation.note`。领域目前可用“自然经验、个体体验、社会与制度、历史变化、知识实践”；它只在点击节点后的详情中显示，不进入 SVG 节点，以免把主图变成标签墙。若一项历史事件、制度变化或公共实践确实改变了问题条件，可在 `observation.historyLinks` 中保存阶段、同期回应及可选事件 ID。历史链接是语境入口，不等于该事件单独造成了后续哲学结论。

### 问题

问题是需要回答的困难、张力或解释要求。它可以由一个或多个观察提出，也可以由一个或多个答案产生。开放问题仍使用“问题”类型；是否已有回答由边决定。

写问题时必须区分历史人物确实提出的问题、原书可合理重建的问题，以及本站为比较而归纳的“问题家族”。文字相似不等于两个时代的人在回答完全相同的问题。

### 答案

答案是对问题的具体回应，必须至少有一条来自问题的“回应问题”边。`answerRole` 记录主要回答动作：`提出`、`区分`、`反驳`、`修复`、`转向`或`综合`。这些是元数据，不是新节点类型。

答案通常会产生新问题，但不强制每条支线都在当前图中继续。若史料或当前范围不足，应让问题保持开放，不能为了图形对称而发明联系。

## 4. 三种逻辑关系

| 起点 | 终点 | 关系 | 含义 |
| --- | --- | --- | --- |
| 观察 | 问题 | 提出问题 | 经验或处境为何迫使人提问 |
| 问题 | 答案 | 回应问题 | 方案具体回应哪项解释要求 |
| 答案 | 问题 | 产生问题 | 答案留下什么代价、矛盾或新任务 |

没有“答案 → 答案”捷径。若一个理论批评或修复另一个理论，必须显式写出两者共同面对、或前一答案产生的问题。

每条边还要保存简短的 `label` 和证据性质 `connection`。

## 5. 连接证据等级

`ProblemConnectionKind` 保留五类：

- `原书线索`：罗素正文直接给出或强烈暗示；
- `历史回应`：有充分材料支持后者回应前者；
- `同题并列`：可放在同一问题下比较，但不声称直接影响；
- `本站推演`：为了揭示逻辑压力而作的编辑性重建；
- `后世重构`：主要由后世作者或现代研究者组织出来。

逻辑关系和证据性质是两个维度，界面必须同时保留，不能把所有箭头都误读成真实影响史。

第一层把自然经验拆为五个可重叠的观察维度：并存多样、时间中的状态变化、条件与结果的可重复关联、持续／往复／周期模式，以及构成更替时仍被认作同一的过程。拆分是为了让每种经验压力分别连向同一、动力或秩序问题；“因果”和“自然规律”仍属于后续问题与答案，不能预先塞进观察节点。

观察在整张图中反复作为检查点重新进入：爱奥尼亚知识网络关联自然差异，雅典公共生活关联共同判断，生物研究关联组织与功能，政体比较关联好生活，马其顿征服关联个人伦理，罗马法律关联世界城邦，三世纪危机关联内向与超越。历史概览不是被复制进图谱；只有确实改变问题条件的事件或制度才成为观察或历史入口。

### 7.1 五档阅读密度

呈现压缩不得删除 `problem-map-data.ts` 中的原子节点、边或稳定 ID。当前五档为：

1. **导览**：只显示五个问题家族的关键锚点；节点按问题家族分列，背景按历史时期分段，用于建立“历史时期 × 问题家族”的低成本方向感。
2. **主干**：保留观察、分叉、汇合、跨阶段锚点和开放问题；被隐藏的一进一出节点由可辨认的折叠路径跨过。
3. **标准**：默认档。保留全部分支，把同一维护阶段内连续的一进一出节点压成可点击展开的论证链；当前选中链内节点时必须恢复其原子步骤。
4. **完整**：显示全部原子节点与原始边，不做折叠。
5. **研究**：节点范围与完整档相同；左侧额外列出当前节点全部进入／发出关系的方向、标签与证据性质，用于内容审核。

每档必须在界面中显示自己的组织说明、当前可见节点数、原子节点总数及隐藏／折叠数量。档位偏好可以保存在当前浏览器，但不得进入 Git 或改变跨设备内容状态。

### 7.2 折叠、聚焦与历史背景带

- 连续论证链只在内部节点严格为一进一出、且没有跨越维护阶段时自动形成；点击折叠节点可展开全部步骤，左侧同时列出链内节点。未来新增章节若连接到链内节点，原始 ID 与边仍可直接成为新分叉。
- 主干与导览隐藏节点后必须沿原边追踪到下一个可见节点，生成明确标记的折叠路径；折叠路径不冒充一条新的原始哲学关系。
- “一跳／两跳”局部聚焦临时显示所选节点的前后邻域并压缩空行；退出后恢复当前密度全图，不重写任何节点的 `graph.row/lane`。
- 历史阶段以可点击背景带进入现有历史概览。维护分组仍只服务数据编辑，不能伪装成历史时期。
- 五个问题家族只用于导览锚点和方向辨认，不把不同年代的问题硬合并成永恒同一问题。
- 解释边界放在左侧详情，可被搜索与审核，但不为每个现代校正额外增加主图节点。
- 并行答案扇面必须由共同问题组织竞争答案；哲学家仍只作为参与者与下钻入口，不能成为压缩分组。

### 7.3 主题标签与“自我”多分辨率试验

问题图谱正在从单一组织尺度扩展为两个互不替代的控制维度：主题筛选回答“看哪类问题”，压缩层级回答“以多大分辨率阅读”。五个主题按 `方法 → 自然 → 自我 → 社会 → 终极` 排列；它们是可交叉的阅读坐标，不是互斥学科。节点可以拥有多个主题标签，但原子节点仍只有一个稳定 ID 和一个视觉实体。

当前先完成“自我”首轮修订，其他四个主题在界面中保留顺序但暂不启用。`app/problem-map-self-data.ts` 保存5／10／20总结树与原子入口；`app/self-reading-data.ts` 保存每个论证组的确切节点归属、28条明确标注的阅读关系与跨主题接口。`app/knowledge-paths.ts` 提供粗层关系聚合及人物／流派／历史反向索引；`app/knowledge-connections.tsx` 在三类页面展示共用论证。四种分辨率为：

1. **5**：五个核心问题，卡面直接显示具体提问和简明回答比较，详情解释分歧与继续追问的理由；
2. **主线10**：十组主要问题与分歧；
3. **论证组20**：二十个具体论证组，明确参与者和问题边界；
4. **全部节点**：显示本轮整理的167个自我相关节点及180条内部关系；并非穷尽一切自我哲学。

同一个维护阶段不再作为整批归属依据。父卡严格取子卡节点的并集，每层覆盖同一批知识。粗层箭头由跨组原子边聚合，虚线表示共享节点；详情列出依据及核对入口，不再因卡片相邻而自动连线。13条新增连接为同题并列，15条为本站推演，均不冒充直接历史影响。10／20组仅绘制当前卡的相接关系以控制拥挤。

5／10／20层的总结节点必须明确标记“本站学习重构”，并保存覆盖的问题阶段；它们不能加入原子节点数组，也不能冒充历史人物的原话或新的原始关系。单击总结节点查看详情；双击或 Enter 按5→10→20→全部下钻，空格只选中，按钮提供相同的触屏操作。展开总结层时定位到当前卡片的第一张子卡，展开20层时定位到该卡 `entryNodeId`；不能仅切换档位后回到第一张总览卡。节点挂载并完成布局后，再无动画滚动至视口中间并转移键盘焦点。直接切换层级也按当前分支或原子节点的历史阶段定位。进入原子节点后保留现有详情、人物／流派／章节下钻和返回链。

旧版50节点档已移除，`ahowp-problem-map-self-compression` 中保存的 `50` 自动迁移到 `all`。选中总结卡用 `ahowp-problem-map-self-summary` 单独保存，不改变原子节点 ID 或全图密度偏好。

层级按钮右侧的左箭头按全部→20→10→5返回一级，同时恢复总结卡选择和定位。返回必须优先使用此前保存的总结卡 ID，尤其不能把共享同一维护阶段的两张20层卡片混为一张；5层时左箭头禁用。它是层级返回，不是浏览器历史后退。

当前自我标签既包含主线，也包含与方法、自然、社会和终极直接相接的接口节点。标签表示相关性，不表示节点只能属于自我。后续增加其他主题时应复用稳定节点 ID；多选默认取并集，共有节点只显示一次，经过未选主题的中间关系必须标记为折叠路径或桥接，不能伪造成直接历史影响。

内容审计同时验证主题顺序、四档分辨率、总结树的5／10／20严格节点数、原子及阶段 ID 存在性、20层入口属于本卡覆盖的自我节点，以及5节点层覆盖全部自我相关原子节点。导航回归测试覆盖非首张卡下钻、共享阶段的不同入口、上返分支、原子入口覆盖与旧偏好迁移。只有完成真实阅读校正后，才能把同一结构复制到方法、自然、社会与终极。

## 8. 状态、搜索与返回

- `mode = "problems"`；
- `problemPhaseId` 暂时保留为兼容旧会话和搜索定位的内部字段，不再驱动可见阶段导航；
- `problemNodeId` 保存当前节点，进入人物、流派、章节或历史概览后仍可精确恢复；
- 从节点进入人物或章节前保存图谱来源和窗口位置；
- 返回后恢复图谱与原来的阅读位置；
- 从历史观察进入历史概览时保存 `problemHistoryOrigin`；历史页显示专用返回条，恢复原节点和纵向位置；
- 搜索覆盖节点正文、答案角色、观察领域与说明、历史链接、参与者，以及边的关系、标签和证据类型。

添加第二条谱系前必须先引入 `problemMapId`，同步改造本地恢复、搜索定位和返回来源，不能只向数组追加对象。

## 9. 扩展步骤与内容边界

1. 先列观察、问题和候选答案，不急着画边。
2. 核对每个问题来自哪些观察或旧答案，不把年代先后自动写成“回应”。
3. 核对每个答案回应什么、解决什么、又留下什么。
4. 添加多对多边，为每条边写标签和证据性质。
5. 把人物作为参与者挂到节点，不把人物变回节点。
6. 添加原书章节与可靠来源，争议性归因必须显式降格。
7. 最后安排 `row` 与 `lane`，优先减少交叉并保留从上到下的方向。
8. 同步搜索、文档、审计和离线包。

不得把后世概括写成当事人原话，不得把本站推演伪装成历史影响，不得为了视觉整齐制造不存在的问题，也不得把图退回单线列表或随机漂移的力导向布局。

## 10. 审计与验收

```bash
npm run audit:content
```

内容审计必须验证 ID 唯一、边端点存在、三种方向与关系匹配、答案具有 `answerRole`、每个观察具有领域元数据且没有入边、历史链接指向存在的阶段／回应／事件、答案至少有问题入边、问题至少由观察或答案提出；三卷全部 76 章和现有 82 位人物还必须全部被谱系覆盖。呈现元数据还必须验证五档密度均有说明、五个问题家族的导览列与锚点有效、每个维护阶段具有现存历史阶段映射、解释边界指向现存节点，以及并行答案扇面的成员确实由共同问题以“回应问题”连接。当前内容基线为 1 条谱系、49 个维护分组、826 个原子节点、975 条原始边。
